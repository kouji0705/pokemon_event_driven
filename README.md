# ポケモンバトル イベント駆動

ポケモンバトルのルールを、イベント駆動の考え方で段階的に実装する。

バトル全体の進行はアルゴリズムで管理する。バトル中に起きたことは出来事として順序を残す。最初からすべてのルールは実装せず、単純なケースから分岐を足していく。

## 解決したい課題

| 課題 | 目指す状態 |
|---|---|
| 特性・持ち物の組み合わせが膨大 | 個別の効果を追加しやすくする |
| 処理の順番が複雑 | 発生タイミングと優先順位を明確にする |
| 効果が連鎖する | 何が何を引き起こしたか追跡できる |
| テストの組み合わせが増える | 小さなケース単位で検証する |

特性・持ち物は STEP 07 でタイミング単位、STEP 08 で連鎖を扱う。処理順は各 STEP の前にフローを固定し、行動順は STEP 02 で広げる。連鎖の追跡は STEP 01 から出来事を順に残し、STEP 08 で制御する。テストは 1 STEP につき少数のケースに限る。

## 基本方針

- バトル全体の進行はアルゴリズムで管理する。
- バトル中に発生する出来事をイベントとして整理する。
- イベントの発生タイミングと処理順序を明確にする。
- 最初からすべてのルールを実装しない。
- 単純なケースから始め、段階的に分岐を追加する。

イベント駆動そのものを目的にしない。目的は、複雑なルールを管理しやすくすること。

## 開発対象

初回ターンは複雑なため、最初の開発対象から外す。**2ターン目以降の通常ターン**から実装する。

前提:

- 双方のポケモンが場に出ている。
- バトルの状態がすでに存在している。
- 2ターン目の行動選択から開始する。
- 先発登場と初回ターンは STEP 09 で共通ターン処理へ接続する。

勝敗はターン途中でも確定する。ひんし判定と勝敗判定は、攻撃中とターン終了の両方から呼べる共通処理として STEP 04 で切る。

### 共通ターンで通す経路

STEP 01 で通すのは、次の一本道。

ターン開始 → 双方の行動選択 → 行動順決定 → 先攻の行動 → 後攻の行動 → ターン終了 → 次のターン

ひんしによる交代、ターン途中の決着、ターン終了時のひんしは後続 STEP で足す。

## アルゴリズムの階層

全体フローには細かい条件分岐を書かない。各フェーズの詳細は別のフローとして管理し、実装はシナリオ単位で進める。新しいルールを足すときは、既存フローのどこに影響するかを確認する。

| 階層 | 責務 | STEP 01 で触る範囲 |
|---|---|---|
| LEVEL 1 バトル全体 | 準備・先発登場、共通ターン処理、バトル終了 | 共通ターンの 1 周 |
| LEVEL 2 ターン処理 | 開始、行動選択、行動順、行動実行、ターン終了 | 残行動もひんしもない一本道 |
| LEVEL 3 個別シナリオ | 通常攻撃、失敗、交代、ひんし、特性、持ち物、状態異常、連鎖 | 通常攻撃のみ |

次の処理は特定のフェーズに限定しない。発生する場所と判定処理を分け、STEP 01 では呼ばない。

| 共通処理 | 起きる場所 | 主に扱う STEP |
|---|---|---|
| ポケモン登場時処理 | 交代、先発登場 | 05, 09 |
| ひんし判定 | 攻撃中、ターン終了時 | 04 |
| 勝敗判定 | ターン途中、バトル終了 | 04, 09 |
| 特性・持ち物の発動 | 登場、行動前後、被弾、ターン終了 | 07, 08 |
| 状態変更に伴う追加処理 | 状態が変わった直後 | 07, 08 |

## ロードマップ

前の STEP が完了してから次へ進む。

| STEP | 開発対象 | 完了条件 |
|---|---|---|
| 01 | 基本の1ターン | 双方が攻撃してターンが終了する |
| 02 | 行動順の決定 | 優先度・素早さ・同速を判定できる |
| 03 | 技の成功・失敗 | 命中・回避・無効を処理できる |
| 04 | ひんし・勝敗 | 行動中断と勝敗判定ができる |
| 05 | ポケモン交代 | 通常交代・登場時処理ができる |
| 06 | ターン終了時の効果 | どく・天候・回復等を処理できる |
| 07 | 特性・持ち物・追加効果 | 発動タイミングに応じて処理できる |
| 08 | 複合イベント | 複数効果の順序と連鎖を制御できる |
| 09 | 初回ターン・統合 | 先発登場からバトル終了まで動作する |

各 STEP は次の順で進める。

1. アルゴリズムをフローチャートで整理する。
2. 実装対象のシナリオを決める。
3. 前提条件と期待結果を定義する。
4. 実装する。
5. テストで動作を検証する。
6. 次の STEP へ進む。

### 後続 STEP で足すケース

| STEP | 追加するケース |
|---|---|
| 02 | 優先度が異なる、素早さが異なる、同速、トリックルーム、行動順に影響する効果 |
| 03 | 命中、外れ、タイプ相性での無効、技の失敗、行動不能 |
| 04 | 先攻でひんし、後攻の中断、後続がいる、後続がいない、勝敗確定 |
| 05 | 双方攻撃、一方交代、双方交代、登場時処理、交代の制約 |
| 06 | どく、やけど、天候ダメージ、たべのこし、継続ターン更新 |
| 07 | 登場時、行動前、技を受けたとき、ダメージを受けたとき、追加効果、攻撃後、ターン終了時 |
| 08 | 複数特性、特性と持ち物の連鎖、効果から新しい効果、発動順序、処理途中のひんし |
| 09 | 先発決定、登場、登場時の特性と持ち物、初回ターン、共通ターンへの接続、勝敗まで進行 |

STEP 02 は、STEP 01 の素早さ比較を拡張する。比較処理は 1 箇所に閉じる。

## 現在のフォーカス

**STEP 01: 基本の1ターン / CASE-01: 通常攻撃**

2ターン目から開始し、双方の通常攻撃を処理して 3ターン目へ進める。その間に発生した出来事を順番に確認できること。

### 前提

- 2ターン目から開始する。双方のポケモンは場に出ている。
- 双方が攻撃技を選択する。優先度は同じ。素早さは異なる。
- 技は必ず成功し、命中する。ダメージは固定値。
- 特性、持ち物、状態異常、追加効果、ひんし、交代はない。

### サンプルデータ

動作確認用の仮データ。実際の種族値やダメージ計算とは異なる。

| 項目 | ピカチュウ | フシギダネ |
|---|---|---|
| 開始時 HP | 100 | 100 |
| 素早さ | 90 | 45 |
| 行動 | 攻撃 | 攻撃 |
| 与ダメージ | 20 | 15 |
| 行動順 | 先攻 | 後攻 |
| 終了時 HP | 85 | 80 |
| 終了時 | 生存 | 生存 |

### 発生する出来事

イベント名は仮。契約は順序と内容。STEP 01 の出来事は手順の結果ログとし、購読やハンドラは STEP 07 で導入する。

| 順 | 出来事 | 内容 |
|---|---|---|
| 1 | TurnStarted | 2ターン目開始 |
| 2 | ActionsSelected | 双方の行動が確定 |
| 3 | ActionOrderDetermined | 行動順が確定 |
| 4 | MoveUsed | ピカチュウが技を使用 |
| 5 | DamageApplied | フシギダネの HP が減少 |
| 6 | MoveUsed | フシギダネが技を使用 |
| 7 | DamageApplied | ピカチュウの HP が減少 |
| 8 | TurnEnded | 2ターン目終了 |

### 完了条件

- [x] 2ターン目の状態から実行できる
- [x] 双方の行動を受け付けられる
- [x] 素早さによって行動順が決定する
- [x] 先攻・後攻の順番に攻撃が実行される
- [x] ダメージに応じて HP が減少する
- [x] 発生した出来事を順序どおりに確認できる
- [x] ターン終了後、3ターン目に移行できる

### 作業分解

1. **状態** — ターン番号、双方の HP、素早さ、攻撃、固定ダメージ
2. **手順** — 行動受付、素早さ比較、先攻、後攻、ターン加算
3. **記録** — `TurnStarted` から `TurnEnded` までを発生順に残す
4. **検証** — 行動順、終了時 HP 85 / 80、出来事 8 件、ターン 3

### STEP 01 の対象外

本格的なダメージ計算、技の優先度による行動順変更、同速時のランダム判定、命中・回避判定、急所判定、タイプ相性、状態異常、特性、持ち物、追加効果、ひんし、ポケモン交代、天候・フィールド。
